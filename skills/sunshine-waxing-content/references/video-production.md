# 선샤인왁싱 세로 영상 제작 기준

사용자가 2026-10-19 바탕화면에 받은 영상 3편을 스킬화하도록 요청한 기준이다. 다음 제작의 시작점으로 사용하며 새 요청의 수량·길이·편집 도구를 우선한다.

## 기준 결과물과 편집 원본

- 작업 공간: `C:/Users/mach7/OneDrive/문서/ChatGPT/선샤인 왁싱`
- 고객 제공 소재: `C:/Users/mach7/Downloads/선샤인 왁싱`
- 기준 결과물: 작업 공간의 `output/smartplace_20261019/`
- 기준 편집 스크립트: 작업 공간의 `scripts/create_smartplace_20261019.py`
- 수정 가능한 자막·장면: 기준 결과물의 `project/*.ass`, 장면별 MP4와 로그
- 브랜드 로고: 작업 공간의 `output/pdf/sunshine_place_logo.png`

기준 스크립트는 당시 3편과 경로가 고정된 재현용 원본이다. 다른 작업에서 바로 실행하면 기존 납품물을 덮어쓸 수 있으므로 새 제작용 복사본에서 `OUT`, `WORK`, `DESKTOP`, `REELS`를 바꾼다. 날짜와 필요시 버전을 붙인 새 작업 폴더를 사용한다. 기준 영상과 원본 소재는 보존한다.

## 화면과 자막

기본 출력은 1080×1920, 9:16, 30fps다. 아이보리 면에 브라운 제목, 톤다운 주황 구분선과 작은 강조를 사용한다. 피부에는 주황 필터를 씌우지 않는다.

제목 폰트가 없으면 실제 사용 가능한 한글 명조로 대체하고 출력 화면에서 확인한다. 자막은 단어를 무리하게 늘리거나 복잡한 테두리를 넣지 않는다. 각 화면에는 한 가지 생각만 담는다. 주제·내용이 다르면 기준 문구를 그대로 재사용하지 않는다.

로고 크롭 좌표는 현재 승인된 로고 파일에만 맞는다. 로고가 바뀌면 직접 확인하고 크롭을 다시 잡는다. 워드마크·모노그램의 비율을 유지하고, 마지막 장면에는 큰 로고와 시술별 안내를 둔다.

## 구성과 움직임

기준 3편은 5초·5초·5초·4초의 4장면, 0.45초 크로스페이드 3회로 약 17.65초다. 소재와 메시지가 달라지면 길이는 조정한다.

1. 첫 1~2초: 실제 시술 장면 또는 관련 전 사진과 고객의 질문. 긴 로고 인트로를 앞에 두지 않는다.
2. 중간: 같은 시술의 다른 과정이나 결과를 보여 준다.
3. 전후 자료가 있으면 실제 비교. 없으면 시술 과정·상담 포인트로 구성하며 전후를 만들어내지 않는다.
4. 끝: 로고와 해당 시술의 예약·상담 안내.

첫 장면 자막은 약 0.1초부터 노출한다. 이후 자막은 장면 시작 0.45초 뒤에 들어오게 해 크로스페이드 중 이전 자막과 겹치지 않도록 한다. 기준은 18px의 짧은 상향 이동, 약 0.24초 페이드인·0.4초 페이드아웃이다. 고정 헤드라인은 장면마다 위치가 바뀌지 않게 한다.

사진은 부드러운 미세 확대 정도로 사용한다. 사진만 있는 소재는 사진 기반 전후 영상이라고 구분한다. 실제 동영상이 있으면 시술 동작을 살리고, 같은 장면을 억지로 늘리지 않는다.

## 소재 확인과 전후 비교

- 고객 대화·연락처·다른 업체 로고가 보이는 소재를 제외하거나 허용된 편집 방법으로 해당 영역을 처리한다.
- 같은 사람·같은 부위의 전후인지 확인한다. 시술 효과가 달라 보이도록 털·피부 상태를 생성하거나 보정하지 않는다.
- 상하 비교 시 두 이미지의 방향과 확대율을 맞추고 작은 BEFORE/AFTER 라벨을 쓴다. 신체 변화가 잘리는 크롭은 수정한다.
- 당시 다리 비교는 `KakaoTalk_20261015_180641023_08.jpg`와 `_09.jpg`, 눈썹 비교는 `KakaoTalk_20261015_180702324_02.png`, 뒷목 비교는 `_03.png`였다. 이 매핑은 그 파일에만 적용한다.
- 당시 두 시술 MP4에는 -90도 회전 메타데이터가 있었고, 다리 사진에는 EXIF 회전이 있었다. 새 소재는 ffprobe와 실제 프레임으로 확인하고 자동 회전과 수동 transpose를 중복 적용하지 않는다.

## 편집 도구와 배경음

이번 납품은 FFmpeg+ASS로 제작했다. 브루는 사용자가 허용한 선택지이며 필수가 아니다. 사용자가 브루 프로젝트를 요청하면 실제 브루에서 편집·내보내기를 확인한 뒤 그 결과를 전달한다. FFmpeg 결과물을 브루에서 만들었다고 표현하지 않는다.

기준은 H.264, yuv420p, CRF 18, AAC 192kbps/48kHz, faststart다. 원본 시술음에 사적 대화가 있으면 제외한다. 조용한 사용 허가된 음원을 사용하고, 기준 배경음은 약 -24 LUFS를 목표로 페이드인 0.6초·페이드아웃 1.45초를 적용했다. 음악을 바꾸면 실제 소리를 다시 듣고 급격한 음량 변화·클리핑을 점검한다.

기준 스크립트의 장면 캐시는 ASS 텍스트만 비교한다. **소스·인아웃·크롭·로고·장면 길이 변경 시 기존 캐시를 재사용하지 않는다.** 새 WORK 폴더 또는 새 장면 이름으로 렌더링한다. 길이를 바꾸면 xfade 오프셋과 오디오 트림도 함께 계산한다.

## 문구와 벤치마킹

- 제목은 지역과 시술 부위를 자연스럽게 한 번씩 표시한다. 예: `화곡 눈썹왁싱 | 눈썹 정리, 어디까지 해야 할까요?`
- 본문은 고객 고민 → 실제 영상에서 볼 내용 → 상담 범위 → 해당 시술 예약 안내로 구성한다. 과거 할인·쿠폰은 현재 유효성을 확인한 경우에만 넣는다.
- 경쟁업체를 조사할 때 플랫폼·원문 URL·게시일·조회수 라벨·확인일을 함께 기록한다. 선샤인의 같은 플랫폼·게시 후 같은 기간 수치가 없으면 '우리보다 높다'고 단정하지 않는다.
- 제목·설명만 읽었다면 분석 범위도 그 수준으로 표시한다. 컷·음악·편집 리듬은 실제 재생 내용을 확인한 경우에만 분석한다. 경쟁 영상·브랜드 디자인은 가져오지 않는다.

## 검수와 납품

렌더 후 첫 화면·중간·마지막과 전환 구간을 실제 출력에서 확인한다. 휴대폰 크기에서 한글·로고·전후 라벨·신체 부위가 잘리지 않는지 본다. 재생과 소리를 확인하고, ffprobe로 해상도·프레임률·오디오·길이를 점검한다. 디코드 오류가 있는지 확인하되 검수하지 않은 항목을 완료했다고 기록하지 않는다.

기본 납품은 MP4, 영상별 JPG 표지, 새소식 제목·본문이다. 편집 스크립트와 ASS는 작업 공간에 보관한다. Windows의 실제 바탕화면 경로를 확인해 `선샤인왁싱_영상_{수량}편_{YYYYMMDD}`처럼 알아볼 수 있는 폴더에 복사하고 파일 존재·크기를 확인한다. 링크는 절대 경로로 제공한다.

제작·저장·게시 상태를 각각 구분한다. 새소식 게시가 요청된 경우 로컬 Aside CLI를 우선 사용하고 대상 계정·매장을 확인한다. 전용 프로필이 있으면 해당 `--profile`을 지정한다. 다른 업무가 공유하는 프로필의 계정을 반복 전환하지 않는다. 인증정보는 스킬에 저장하지 않는다. 게시 성공은 실제 관리자·공개 화면에서 확인한 뒤 기록한다.
